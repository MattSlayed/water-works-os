# Riverbend canonical plant (KG steps 0–1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make WaterOS describe the same Riverbend plant as the 3D model and the website mock: 8 filters, HLP-A..E, 100 ML/d, the 3D footprints and the website's tags. Every renamed id goes through one crosswalk.

**Architecture:**
- **Scene export.** A Blender export writes the 3D footprints into `data/riverbend/scene-meta.json`. It uses a site frame that is mirrored, rotated onto the plant axis and level-shifted, so the process blocks come out axis-aligned and no real coordinate or level survives.
- **Layout.** `layout.mjs` builds STRUCTURES and MACHINES from that file through one PLAN table. The drawings, ingest, plant model and web view then follow unchanged.
- **Generator and region.** `generate.mjs` and `region.mjs` take the new counts and renames.
- **Crosswalk.** `data/crosswalk.json` is built by a script and checked by a test. It records every old id → canonical id and every sensor → ISA tag.

**Tech Stack:** Node 22 ESM, `node:test`, zero runtime dependencies; Blender 5.2 in background mode for the one export script.

**Spec:** `docs/superpowers/specs/2026-10-29-riverbend-knowledge-graph-design.md`, §4 (inputs, RES-2), §5 (canonical plant, crosswalk), §6.4 (tag scheme), §10 (constraints), §13 steps 0–1.

## Global Constraints

- **Canonical plant:**
  - F01–F08, in FB-1 (F01–F04) and FB-2 (F05–F08)
  - CL-1..4
  - HLP-A..E in HLP-H (HLP-D standby, HLP-E small duty)
  - RWP-A..C in station RWP-1
  - RES-1/RES-2 on site
  - RWR-1/RWR-2 raw-water reservoirs
  - Site capacity **100 ML/d**
- **Remote reservoirs** RS-RES1/RS-RES2 become **RS-CR1/RS-CR2**, "Command reservoir 1/2".
- **CL-4 is out for refurbishment.** The refurbishment project and its group chat move from CL-3 to CL-4. **PRJ-RES2 relines cell B of the on-site RES-2.**
- **Filter media replacement** (PRJ-FMR) covers **F01–F04**, as drawing rev B already does.
- **Sensor tags.** The 9 `CONTRACT.md` tags keep their numbers. All other tags follow the area rule in Task 2. A tag is unique as a whole string.
- **Telemetry values are not re-baselined in this plan.** Only keys and ids change; the coupled model is plan 3. Reservoir `capacityMl` stays at 20 until plan 3.
- **Fictional-name rule:**
  - Nothing from the reference works enters the repo: no name, real coordinates, real levels, drawing numbers or `RIVERBEND-SITE.md` text.
  - Site frame = Blender frame rotated +21.2° about the origin, y flipped to point south, then translated. Levels = Blender Z + 1450.
- **Repo conventions:** LF line endings (Python patch scripts write with `newline=""`), no new npm dependencies, and the full suite green at every commit.
- **Branch:** `feat/riverbend-canonical-plant` off `main`.

**Tag rule (the spec leaves the remainder to the builder; these are the values):**
- **Letters by sensor key:**
  - turb, cl, ph → AIT
  - flow, in, out → FIT
  - headloss → PDT
  - level → LIT
  - press → PIT
  - temp_de, temp, temp_dis → TT
  - vib_de, vib → VT
  - current → IT
  - torque → WT
  - stroke, pos → ZT
  - state → YS
- **Overrides:**
  - SEN-RAW-turb → AIT-101
  - SEN-RAW-flow → FIT-102
  - SEN-DP-2-flow → FIT-201
  - SEN-CLR-turb → AIT-301
  - SEN-F07-turb → AIT-157
  - SEN-F07-headloss → PDT-157
  - SEN-FIN-cl → AIT-401
  - SEN-RES-2-level → LIT-501
  - SEN-HLP-B-temp_de → TT-612
- **Filters:** `<letters>-15<bay>`, so F03 turbidity is AIT-153.
- **Everything else:** area digit by zone (Z01 1, Z02 2, Z03 2, Z04 3, Z06 4, Z07 storage 5 / high-lift pumps 6, Z08 7, Z09 2, Z10 6, remote 8). The next free number from `area*100+1` is taken in sorted sensor-id order, skipping any tag string already used.
